# 金铲铲长期赛季研究资料库

## 赛季机制整理（按玩法系统，而非把所有东西叫棋盘效果）

依据本地中央游戏 Skill `game-teardown-framework`（机制证据链、观察与解释分离）与
`game-data-extraction-framework`（来源优先、结构先行、缺失不编造），原有
`tables/棋盘可能效果.csv` 的 **1,563 条官方候选和公告记录完全保留**，并由
`mechanism_catalog.py` 生成包含 16 列的 `tables/赛季机制图鉴.csv` 和
`data/mechanism_overview.json`。旧表用于追溯，新表用于设计分析及 Web 浏览；
数据依然是选定配置快照，并非每个历史补丁的完整清单。

对外图鉴按玩家接触机制的位置分类：

| 分类 | 记录 | 与玩家操作的关系 |
|---|---:|---|
| 对局环境与全局规则 | 790 | 对局环境、经济／规则变化；仅银河战争明确称星系，其余标「全局规则候选」 |
| 赛季专属互动 | 456 | 自然仙灵 348、画之灵奇遇 108；不是棋盘地格 |
| 主动购买与使用 | 181 | 法杖／一次性道具效果，包括经济、战力、羁绊等子类 |
| 羁绊影响的站位 | 130 | 羁绊对布阵位置的影响，**并非独立赛季主机制**；默认列表排除，可单独查 |
| 赛季公告与补充 | 6 | 有来源的公告／历史补证，不等同于官网同版本实装验证 |

Web「赛季机制」先展示所选赛季的系统构成与数量，再提供系统类别筛选与具体规则卡。
另有 `data/season_signatures.json` 保存**14 种主题的标志性赛季主玩法**：每条把
可观察规则、玩家实际需要做的选择和公开来源分开，显示在系统构成之前；
没有单独找到足够来源的赛季会显示「待来源核实」，而不是用配置表里最多的效果
猜测官方设计。对于同名返场的不同 SDK 版本，只能说明**主题级主机制**，不表示
各次返场的流程、数值和出现回合完全相同。
规则卡包含**来源、触发条件、作用范围、设计层级、是否独立机制、分类依据和核验状态**。
不根据配置文件名杜撰赛季设计意图，尤其是 `galaxy.js` 并不意味着所有赛季都是星系。
无数据的赛季会明示未取得记录，不借用相邻模式。

Excel 新增第六张「赛季机制图鉴」，保留第五张「海克斯强化」及原始四表。增量更新：

```powershell
python mechanism_catalog.py
python export_mechanism_excel.py   # 可选，需 openpyxl
python research.py build            # 自动重新整理 CSV 并更新工作簿
```

## 海克斯／强化符文（新增）

已从腾讯官网版本索引所指向的 `hexurl` 静态配置中，将各玩法的代表性补丁分别解析为 `tables/强化符文.csv`。目前 **41 组历史玩法中有 37 组包含可用强化资料，共 10,478 条按赛季独立记录**（同名强化跨赛季分别保留）；其余 3 组官方静态强化列表为空，1 组历史官方资源不可用。空列表**不等于**游戏当时确定不存在强化。

Web 「海克斯强化」页支持按赛季、强化名称或效果、银／金／彩及特殊等级、历史配置版本筛选，查看官方图标、完整文本、原始等级与来源；`data/augment_coverage.json` 记录 41 组覆盖与缺口。官网等级 4、7 等特殊强化保留原始数值，不能全部归为普通三级。

第五张「海克斯强化」和第六张「赛季机制图鉴」均已加入 `金铲铲全赛季研究资料库.xlsx`；原有四张研究表保留。

```powershell
python augment_catalog.py            # 基于本机已采集的腾讯JSON刷新CSV
python export_augments_excel.py       # 可选：把强化表加入Excel（需 pip install openpyxl）
python -m unittest discover -p "test_*.py"
```

在没有 `source/` 原始下载文件的 GitHub 克隆上，已提交的海克斯 CSV 和覆盖清单可直接由 Web 使用；不需要再次抓取。**数据是选定补丁的配置快照，并非197条历史补丁每一期的所有强化集合，也不意味着每条一定可在当时实战选择。**

## GitHub 公开版说明

本仓库公开了本地 Web 图鉴、Python 数据采集与整理脚本、已整理的国服 CSV 资料、Excel 和轻量官方赛季图片索引。克隆后运行 `python web_server.py`，访问 `http://127.0.0.1:8765/` 即可查看全赛季图鉴（需要 Python 3.10+，无需安装第三方 Python 包）。

大型第三方原始 JSON 抓取快照位于 `source/`，不随公开仓库分发。研究生产与深度回归测试若需要这些历史原始文件，请使用 `collect_official_index.py`、`collect_official_jcc.py` 和 `collect_official_patches.py` 按来源自行构建。无原始资料时，Web 浏览、筛选和已整理数据可正常使用，依赖原始文件的研究测试将跳过。

这是非官方、非商业的资料整理项目。游戏名称、英雄形象、相关图片和原始配置等权利归原权利方所有；公布数据并不表示取得对原始游戏资源的再授权。请勿直接将本仓库视为腾讯官方 API 或完整的官方补丁档案。

## Tailscale 手机访问（可选）

手机打开 Tailscale 并连接到与 Windows 电脑相同的 Tailnet。电脑侧可以用 Tailscale Serve 提供私有 HTTPS：

```powershell
python web_server.py --no-browser
tailscale serve --bg --https=8443 http://127.0.0.1:8765
tailscale serve status
```

使用最后一条命令所显示的个人 Tailnet HTTPS 地址（带 `:8443`）在手机访问。**不要将自己的 Tailnet 域名、账户信息、访问令牌提交到公开仓库。**

- 可选 Windows 当前用户的任务计划程序 `JCC_Archive_Tailscale`：在每次登录时启动 `web_server.py --no-browser`，避免依赖保持 CMD 窗口打开。该计划任务是**本机配置**，克隆仓库后不会自动创建。
- 使用 Tailscale Serve 而非 Funnel，不需要公网端口映射；如果其他本地应用已经使用 HTTPS 443，独立配置 8443 可以避免覆盖它。
- 电脑需要保持运行、已登录并连接 Tailscale；电脑睡眠或手机上的 Tailscale 未连接时将无法访问。
- 电脑本地仍可用 `http://127.0.0.1:8765/`；启动 `启动铲研Web.bat` 会优先打开已运行的服务，不重复占用端口。
- 这里是 Tailscale 的私有接入入口，界面自身没有额外的账号密码；请使用自己的 Tailnet 访问策略控制能看资料的设备。

## 全赛季图鉴 Web（默认使用方式）

**电脑双击 `启动铲研Web.bat`，浏览器打开 `http://127.0.0.1:8765`；手机版使用自己 Tailnet 的 HTTPS 地址。**

这版以常见金铲铲图鉴站的玩法为参照：先选赛季，再浏览带游戏头像和稀有度颜色的棋子图鉴；支持按费用、羁绊、技能、配置版本搜索，点击棋子查看技能/完整数值和来源；羁绊以官方图标、成员及各人数档位展示。棋盘机制、赛季特色、逐补丁变化独立成页。

参考：`https://www.dataj.cc/database/hero`、`https://jcc.np5.top/tools/seasons/s18`。只借鉴资料库信息组织与交互，不声称与参考网站有合作或复制对方资源。

**全赛季覆盖口径：** 腾讯官网版本索引中的41组独立赛季/返场玩法，以及另行保存的早期开服历史配置与研究记录，均在左侧导航可选。41组中39组有可用棋子+羁绊快照，其余两组会显示为缺失/未完整，不拿其他赛季代替。点击左侧「全部赛季」可跨赛季检索；默认进入近期「自然之力」。

- 不需要 npm、数据库、云服务器或额外账号；Python 标准库的 `web_server.py` 仅监听电脑的 `127.0.0.1`，Tailscale Serve 通过本地反向代理让 Tailnet 内的手机访问，不直接开放给互联网。
- 网页是**只读**研究入口：`tables/*.csv` 是数据来源，不要在网页修改原始事实；继续通过现有研究脚本整理，再刷新网页自动加载新的 CSV。
- Web 已支持独立的「补丁变化」页，使用 `tables/官方逐补丁变化.csv`，只展示具体字段差异，不把所有字段变化擅自认定为平衡性修改。
- 不使用第三方前端框架或 CDN；棋子与羁绊图标直接引用腾讯第一方图片资源（显示图片时需要能访问官方图片域名），文字和技能数据由本机 CSV 提供。必须通过启动脚本打开本机服务，不能直接双击网页文件。图片无法取得时仍可阅读中文文字、费用与技能效果。
- 也可以命令行运行 `python web_server.py --no-browser`。关闭启动窗口即可结束服务，端口被占用时可指定 `--port 8766`。
- 仍保留原始 JSON、研究笔记和六张 Sheet 的 Excel；Web 并不取代采集、核实与导出流程。

目标：持续研究棋子、羁绊效果、棋盘机制、赛季特色，不再一次性抓取并硬编码所有赛季知识。

**全量批次完成（2026-10-15）：** 从腾讯官网实际使用的游戏数据 SDK 发现官方版本索引 197 条记录，对应 41 组金铲铲玩法/赛季；39 组已抓取并规范化棋子/羁绊，另 1 组官网资源返回 404、1 组羁绊字典为空。已取得的官方版本包括至 2026 年的自然之力和限时返场。**这些是每组一个代表性版本，不是逐补丁全集或所有历史首发日原始数据。** 参见 `research-all-seasons-2026-10-15.md` 和 `source/official_jcc_bulk/manifest.json`。最终Excel为 `金铲铲全赛季研究资料库.xlsx`。

选定一个赛季/补丁 → 检查既有快照和缺口 → 抓取新来源 → 标准化候选 → Agent 对照国服官方资料人工判断 → 保存证据与核验状态 → 生成四张原始资料表与两张派生图鉴表。

## 数据所有权

**数据组成：** Excel的国服中文版包含历史第一方配置、39组官网有效玩法代表版本、明确标注版本与出处的国服研究补充。已拆分**星系环境、画之灵奇遇、自然仙灵、法杖/一次性效果、站位相关羁绊**；其中大量属于事件而非棋盘地格，不得把1,563条统称为地格效果。两组官方版本数据依然缺失，已在“赛季特色”中标为未补齐。

1. source/setNN.json 是历史候选数据快照。refresh 会先备份原快照到 source/history 再替换指定赛季。不要手工覆盖历史证据。
2. research_notes.json 保存赛季特色、机制和人工核验证据；不要把观点或链接写死在 Python。
3. research.py 只执行重复劳动。tables/ 和 Excel 是输出，不是事实源；用户/Agent 的持久修订必须在 research_notes.json。
4. `export_excel.ps1` 只做 Windows Excel 展示；如本机 Excel 授权阻止写入，则 `research.py build` 自动尝试用 `repair_xlsx_from_csv.py` 对已有同尺寸工作簿做安全内容更新，保留既有筛选和格式；行列变化时拒绝冒险覆盖。

## 操作方式

在本项目目录下运行：

    python research.py status
    python collect_official_index.py
    python collect_official_patches.py
    # 必须重新抓取所有已存在版本时才使用：python collect_official_index.py --force
    # 2022历史配置的4个模式保留在源数据，不需要每天重拉
    python research.py build
    python research.py refresh --season 12 --patch 14.18 --dry-run
    python research.py refresh --season 12 --patch 14.18
    python research.py mark --season 2 --kind mechanism --id "2|元素格：海洋|原赛季待核验" --status "已核实" --source "https://example.org/source"
    python -m unittest discover -p "test_*.py"

`collect_official_index.py` 每次获取官网版本索引，未变化的玩法快照复用缓存，新增或变化版本才下载。`refresh` 仅处理国际服TFT参考，不替代金铲铲国服。重复 `build` 若CSV未变化则不重复导出Excel。索引404或关键羁绊缺失的玩法保留缺口，不用其他玩法数据偷换。

## 证据标准和风险

**正式主表已改为国服中文内容，国际TFT数据不再混入。** 不过国服官网共41组玩法索引中仅39组可获得完整代表版本；原始历史补丁195条中有8条404或数据不完整；具体缺口保留在官方索引清单。不能因此断言全部历史补丁、机制触发率、棋子商店资格都已实机核实。
每次研究先读 status 和 tables/latest_report.json，聚焦一个版本或一个争议点，优先国服官方资料，再查 Riot 官方与历史社区。附上可追溯的 URL 后才能标记为「已核实」；有冲突就标记冲突、保留原始版本。
S1/S2 网页快照暂为固定历史资料，不能伪装成国服客户端数据。游戏客户端 @变量@ 不等于已展开的玩家可读数值。
自动化只负责机械步骤；是否开始下一轮研究，需要人工发起或明确配置定时任务。本项目不会自行后台运行。
